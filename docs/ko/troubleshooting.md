# 문제 해결

실제 구축·운영에서 겪은 것들과, 원인을 찾기까지 오래 걸렸던 이유를 함께 적었다.
증상이 애매한 것부터 확인하는 것이 빠르다.

## 세션이 안 뜬다

### Pending에서 풀리지 않는다

```bash
kubectl -n giosk-<user> describe pod <pod>       # Events 확인
# 콘솔에서도: 관리자 → 세션 → describe
```

- **PVC 바인딩 대기** — 세션 홈/볼륨 PVC가 Bound 되기 전에 Pod를 만들면 고착된다.
  현재는 바인딩을 기다린 뒤 Pod를 만든다. 단 `WaitForFirstConsumer` 스토리지클래스는
  Pod가 있어야 바인딩되므로 대기 대상에서 제외한다 — 이 예외를 빠뜨리면 반대로 영원히
  기다린다.
- **RWX 클래스 불일치** — `storage.persistence.storageClass`와
  `nfsProvisioner.storageClassName`이 다르면 영속 홈 PVC가 잡히지 않는다.
- **노드 핀** — 특정 노드를 골라 만든 세션은 그 노드에 자리가 없으면 다른 노드로 가지 않는다.
  오류 코드 `node_pinned`가 이 경우다.

### "가용 없음"인데 GPU는 놀고 있다

- **공유(shared)만 가용 없음** → 오퍼링의 `gpu_type`이 노드의
  `nvidia.com/gpu.product` 라벨과 글자 단위로 일치하는지 확인한다. 이 불일치는 아무 로그도
  남기지 않아서 찾기 어렵다.
- **전용 개수가 이상하다** → 물리 GPU 개수는 GFD 라벨에서 읽어야 한다. HAMi가 광고하는
  capacity를 물리 개수로 쓰면 가용량이 부풀려진다.
- **전용 상한이 낮게 보인다** → 상한은 클러스터 합계가 아니라 단일 노드의 유휴 최대치다.
  의도된 동작이다(세션은 노드를 걸쳐 뜰 수 없다).
- 공유 세션은 `share_mode=hami`인 노드에만 배치된다. 노드 설정을 확인한다.

## 접속이 안 된다

### 웹 터미널이 검은 화면이거나 바로 끊긴다

- 프레임을 **바이너리로** 보내야 한다. 텍스트 프레임은 서버가 거부한다.
- nginx 앞단에 프록시가 있다면 WebSocket 업그레이드 헤더를 통과시켜야 한다.

### 게이트웨이 웹소켓이 1006으로 끊긴다

프록시가 `Host` 헤더를 바꾸면 code-server가 오리진 검사에서 거절한다. 원본 Host를 유지해야
한다. 게이트웨이 진단 로그는 ws와 거부 건만 남기므로 이 증상이면 바로 보인다.

와일드카드 인증서 범위도 확인한다. `*.example.org`는 `a-b.gw.example.org` 같은
2단계 이상 하위 도메인을 커버하지 않는다.

### SSH가 거부된다

- 컨테이너 직접 SSH는 `authorized_keys`를 Secret으로 마운트한다. 키를 새로 등록했는데
  반영이 안 되면 Secret이 갱신됐는지 확인한다.
- 물리 노드는 **IP로 접속**한다. 클러스터 DNS에는 노드 이름이 없다.

## 지표가 비어 있다

- **세션 GPU 지표가 전부 0/빈값** — DCGM은 워크로드 Pod 이름을 `exported_pod` 라벨에 넣는다.
  `pod` 라벨만 보고 쿼리하면 오류 없이 빈 결과가 온다. VRAM이 0으로 보이거나 유휴 리퍼가
  동작하지 않는 증상의 원인이 대부분 이것이다.
- **GPU 사용률이 0인데 학습은 돌고 있다** — GeForce 계열 + 최신 드라이버 조합에서 DCGM
  utilization이 0으로 오보고된다. VRAM·전력·온도·클럭은 정상이므로 유휴 판정에는 전력을
  함께 본다.
- **타임슬라이싱은 세션별 측정이 불가능하다.** 분할 GPU의 세션별 지표가 필요하면 HAMi를 쓴다.
- **모니터링 미설치** — 지표 자리에 `—`가 표시된다. `monitoring.install: false`인데
  `prometheusURL`을 안 준 경우다.

## 과금·크레딧이 이상하다

- **크레딧이 줄지 않는다** — `billing.mode`가 `free`이거나 GPU 단가가 0이다.
- **잔액이 0이라는 알림이 반복된다** — 지갑은 (사용자, 팀) 단위다. 다른 팀 지갑을 보고
  있지 않은지 확인한다.
- **사용량이 엉뚱한 팀에 잡힌다** — 세션은 생성 시점의 활성 팀에 귀속된다. 팀을 바꾸고
  만든 세션은 그 시점 팀 소속이다.
- **조직/팀 삭제가 안 된다** — 의도된 가드다. 사용자·멤버가 남아 있으면 지울 수 없다.

## 데이터셋

- **캐시가 안 끝난다** — 압축 해제 단계는 오래 걸린다. 진행률은 단계별로 계산해 표시한다.
  `pigz`가 있으면 병렬 해제하고, 없으면 gzip으로 떨어진다.
- **용량이 실제와 다르다** — 등록 직후에는 압축 해제 후 실제 크기를 재계산한다.
- **삭제했는데 노드에 남았다** — 캐시 진행 중이던 노드까지 정리한다. 그래도 남아 있으면
  캐시 hostPath(`GIOSK_DATASET_CACHE_HOSTPATH`)를 직접 확인한다.

## 디스크가 찬다

```bash
kubectl -n giosk get pods -o wide     # 어느 노드인지
# 콘솔: 관리자 → 스토리지 (노드 디스크 / NFS / 사용자별 할당)
```

점유 주체는 보통 셋 중 하나다 — 중단 세션의 홈 PVC, scratch, 데이터셋 로컬 캐시.
`nodeCleaner`가 임계 기준으로 정리하지만, 중단 세션이 쌓이는 구조적 원인은
`quota.maxStoppedSessions`로 막아야 한다.

## 로그 보는 곳

```bash
kubectl -n giosk logs deploy/giosk-api -f
kubectl -n giosk logs ds/giosk-node-agent
kubectl -n giosk logs deploy/giosk-gateway
```

세션 생성 실패는 API 로그에 매핑되지 않은 오류까지 남긴다. 감사 로그(관리자 → 감사)에는
누가 무엇을 했는지가 남으므로 사용자 문의 대응 시 먼저 본다.
