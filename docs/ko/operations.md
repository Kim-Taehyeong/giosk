# 운영 가이드

설치가 끝난 뒤 실제로 굴릴 때 필요한 것들.

## 초기 구성 순서

1. **조직·팀 생성** — 학과/연구실 단위. 세션 생성에는 팀 소속이 필수다.
2. **GPU 단가 설정** — 관리자 → 빌링 → GPU 단가. 단가가 0이면 크레딧이 줄지 않는다.
3. **크레딧 배분** — 조직 풀 → 팀 풀 → 멤버 순서. 팀 담당자에게 배분 권한을 넘길 수 있다.
4. **정책 한도** — 동시 세션 수, 중단 세션 수, GPU 개수, VRAM, 볼륨 쿼터.
   전역값을 조직·팀·사용자가 덮어쓴다.
5. **오퍼링 정의** — 공유 GPU를 어떤 규격으로 나눠 줄지. `gpu_type`은 노드의
   `nvidia.com/gpu.product` 라벨과 **글자 그대로** 같아야 한다.
6. **이미지 등록** — 외부 이미지를 등록하거나 Kaniko로 빌드한다.
7. **알림 규칙** — 노드 다운, 디스크, GPU 온도, 크레딧 잔액, 세션 사용량.

## 매일 보는 화면

- **운영 대시보드** — 사용 중 세션·사용자, 크레딧 소모 추이, 경고 피드
- **인프라 대시보드** — 노드/GPU 사용률 추이(6/12/24시간), 디스크, 모니터링 상태
- **노드** — GPU 가용량, cordon 상태, 캐시된 데이터셋, 디스크 여유

경고 피드는 두 대시보드에 나눠 담긴다. 플랫폼·노드 수준 경고는 인프라 대시보드에,
사용자·세션·크레딧 경고는 운영 대시보드에 뜬다.

## 알림

전달 경로는 웹훅과 SMTP 두 가지이며, 콘솔 인박스에도 쌓인다.

| 규칙 | 트리거 |
|------|--------|
| `node_down` | 노드 NotReady |
| `gpu_util` / `gpu_temp` | 임계치 초과 지속 |
| 디스크 | 노드 디스크 사용률 |
| 크레딧 | 팀·개인 잔액 하한 |
| 세션 사용량 | 세션의 GPU/CPU/VRAM이 임계치 아래로 지속(자원 낭비 탐지) |

SMTP는 `smtp.host`/`port`/`username`/`password`/`from`으로 설정한다. 비밀번호는
Secret(`smtp-password`)으로 주입된다.

## 자원 회수

- **유휴 세션** — `idle.timeoutMin` 동안 유휴면 중지한다. GPU 사용률만 보지 않고
  전력 소비를 함께 본다(GeForce 계열에서 DCGM 사용률이 0으로 오보고되는 사례가 있다).
  CPU 세션은 회수 대상이 아니다.
- **물리 임대** — 유휴가 이어지면 cordon 후 회수한다. 고정 시간 만료는 쓰지 않는다.
- **중단 세션** — 홈 PVC로 노드 디스크를 계속 점유한다. `quota.maxStoppedSessions`로
  개수를 제한하고, `stoppedTtlDays`가 지나면 정리 대상이 된다.
- **노드 디스크** — `nodeCleaner` DaemonSet이 scratch(85%)와 세션 홈(92%)을 임계 기준으로
  비운다. 최근 `homeMinAgeDays` 이내에 쓴 파일은 건드리지 않는다.

## 백업

복구 시 반드시 필요한 것은 **MySQL**이다. 세션 Pod는 다시 만들면 되지만 사용자·조직·지갑·
감사 로그는 여기에만 있다.

```bash
kubectl -n giosk exec deploy/giosk-mysql -- \
  mysqldump -u root -p"$PW" --single-transaction giosk > giosk-$(date +%F).sql
```

함께 챙길 것:

- NFS export (영속 홈 `~/nfs`, 볼륨, 데이터셋) — 스토리지 쪽 스냅샷 정책으로
- `my-values.yaml`과 게이트웨이 비밀값(공유 토큰키, SSH 개인키)
- 세션 홈은 노드 로컬이라 **백업 대상이 아니다.** 사용자에게 중요한 산출물은 `~/nfs`나
  볼륨에 두라고 안내해야 한다.

## 업그레이드

```bash
helm upgrade giosk charts/giosk -f my-values.yaml
```

- 마이그레이션은 API 기동 시 자동 적용된다(`backend/internal/store/migrations`).
  롤백 스크립트는 없다 — 업그레이드 전 덤프를 받는다.
- API를 여러 replica로 굴려도 승인 구간은 네임드 락으로 직렬화되므로 무중단 롤링이 가능하다.
- 실행 중인 세션 Pod는 API 재시작의 영향을 받지 않는다. 다만 웹 터미널 WebSocket은 끊긴다.

## 용량 계획 감각

- 공유(HAMi) GPU는 VRAM 기준으로 나눈다. 오퍼링을 너무 잘게 쪼개면 컨텍스트 스위칭으로
  전체 처리량이 떨어진다.
- 데이터셋을 노드 로컬 캐시로 올리면 학습 초반 I/O가 크게 줄지만 노드 디스크를 먹는다.
  캐시 대상 노드는 여유 있는 GPU 노드로 한정하는 편이 안전하다.
- 중단 세션 상한을 넉넉히 두면 노드 디스크가 조용히 찬다. 5개 안팎이 무난했다.
