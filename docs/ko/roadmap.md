# 로드맵과 알려진 한계

v0.1.0 기준으로 **아직 안 되는 것**을 먼저 적는다. 되는 것은 [README](../../README.ko.md)에
있다. 여기 적힌 항목은 GitHub 이슈로도 등록해서 진행 상황을 추적한다.

## 알려진 한계

### 인증

- 로컬 계정만 지원한다. **SSO(OIDC/SAML/LDAP) 연동이 없다.** 학내 통합 계정으로 로그인하려면
  연동 계층을 붙여야 한다. 운영 도입 시 가장 먼저 요구되는 항목이다.

### 스토리지

- **볼륨별 실제 사용량을 표시하지 못한다.** 볼륨이 NFS export의 하위 디렉터리라
  `kubelet_volume_stats_used_bytes`가 볼륨이 아니라 export 전체 사용량을 돌려준다.
  실측하려면 하위 디렉터리 `du`가 필요한데 아직 구현하지 않았다. 현재는 할당량만 보여준다.
- 세션 홈은 노드 로컬이라 **백업 대상이 아니다**. 사용자 안내로만 대응하고 있다.

### GPU

- 타임슬라이싱 방식 분할은 **세션별 사용량 측정이 불가능하다.** 세션 단위 관제가 필요하면
  HAMi를 써야 한다.
- GeForce 계열 + 일부 최신 드라이버에서 DCGM utilization이 0으로 오보고된다. 전력 보조
  신호로 우회했지만([ADR-0005](adr/0005-idle-detection.md)) 근본 해결은 아니다.
- 세션이 노드에 묶인다([ADR-0004](adr/0004-session-local-home.md)). 중단 세션을 다른 노드로
  옮기는 마이그레이션 경로가 없다.

### 운영

- DB 마이그레이션에 **롤백 스크립트가 없다.** 업그레이드 전 덤프가 사실상 필수다.
- 단일 클러스터만 관리한다. 멀티 클러스터 페더레이션 계획은 없다.
- 세션 자원 변경(reconfigure) 기능은 랩 환경 실검증이 아직 남아 있다.

### 테스트

- 백엔드 단위 테스트가 얇다. 특히 과금 정산과 크레딧 계층 배분처럼 **틀리면 조용히
  손해가 누적되는** 경로에 테이블 드리븐 테스트를 채워야 한다.
- E2E는 Playwright 시나리오 두 개뿐이다.

## 다음에 할 것

우선순위 순.

1. **SSO 연동** — OIDC를 먼저. 학내 계정 체계와 붙이는 것이 실사용의 전제다.
2. **과금·배분 테스트 보강** — 정산 주기, 잔액 부족 중단, 계층 백필 경로.
3. **볼륨 사용량 실측** — NFS 하위 디렉터리 `du`를 주기 작업으로.
4. **세션 자원 변경 랩 검증** — 노드 핀 제약 아래에서 GPU 붙이기/떼기 시나리오.
5. **설치 경험 개선** — 사전 점검 스크립트(CNI, NFS 쓰기, GFD 라벨, IP 대역)를 하나로.
6. **관리자 가이드 영문화** — 현재 깊은 문서는 한국어만 있다.

## 검토했으나 하지 않기로 한 것

- **VM 임대(KubeVirt + PCI 패스스루)** — [ADR-0006](adr/0006-vm-leasing-deferred.md).
  재검토 조건까지 함께 적어 두었다.
- **CRD/오퍼레이터 전환** — [ADR-0001](adr/0001-kubernetes-native-sessions.md).
- **예산 상한(budget cap) 모델** — 크레딧 계층 배분으로 대체했다. 두 모델을 동시에 두면
  "왜 자원이 안 나오는가"의 원인이 둘로 갈려 사용자가 이해하지 못한다.
