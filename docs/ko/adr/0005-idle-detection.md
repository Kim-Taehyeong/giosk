# ADR-0005. 유휴 판정에 전력을 보조 신호로 쓴다

상태: 확정

## 맥락

GPU를 잡아만 두고 쓰지 않는 세션을 회수해야 자원이 돈다. 처음에는 DCGM이 보고하는
GPU utilization만 보고 판정했다.

랩 환경에서 **학습이 정상적으로 돌고 있는데 utilization이 0으로 보고되는** 사례를 만났다.
GeForce 계열 GPU + 특정 최신 드라이버 조합에서 재현됐다. 같은 GPU에서 VRAM 사용량, 전력,
온도, 클럭은 전부 정상 값이었다. utilization만 0이었다.

utilization만 믿으면 멀쩡히 학습 중인 세션을 회수한다. 사용자 입장에서는 최악의 버그다.

## 결정

유휴 판정에 **전력 소비를 보조 신호로 함께 본다.** utilization이 0이어도 전력이 일정
기준(약 60W) 위에 있으면 유휴로 보지 않는다.

추가로:

- CPU 세션은 회수 대상에서 제외한다(GPU 지표로 판정할 수 없다).
- 전용 GPU 세션은 노드 GPU 지표로, 공유(HAMi) 세션은 HAMi 지표로 판정한다.
- 유휴 HAMi 세션은 "측정 불가"가 아니라 0%로 표시한다.

## 이유

- 오탐(멀쩡한 세션 회수)의 비용이 미탐(놀고 있는 세션 방치)보다 훨씬 크다. 보수적으로
  판정하는 쪽이 맞다.
- 전력은 드라이버 계층이 달라도 비교적 일관되게 보고된다.
- 단일 지표에 의존하는 구조 자체가 문제였다. 신호를 늘리면 한쪽이 틀려도 버틴다.

## 대안

- **드라이버 버전 고정** — 근본 원인 회피는 되지만 운영 제약이 크고, 다른 조합에서 또
  터질 수 있다.
- **프로세스 단위 확인** — 정확하지만 컨테이너 안 프로세스를 들여다봐야 해서 권한 모델이
  복잡해진다.
- **사용자 신고 기반 회수** — 운영 부담이 크다.

## 결과

- 실제로는 놀고 있지만 전력을 쓰는 세션은 회수되지 않는다. 이 미탐은 감수한다.
- 세션별 사용량 알림을 따로 두어, 자동 회수 대신 사용자·관리자에게 먼저 알린다.
- 타임슬라이싱 방식 분할은 세션별 측정이 불가능하다. 세션 단위 판정이 필요하면 HAMi를 쓴다.
- DCGM은 워크로드 Pod 이름을 `exported_pod` 라벨에 넣는다. `pod` 라벨로 조회하면 오류 없이
  빈 결과가 오고, 그러면 모든 세션이 유휴로 보인다. 이 함정 때문에 초기에 유휴 리퍼가
  전혀 동작하지 않았다.
