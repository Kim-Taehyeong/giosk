# ADR-0004. 세션 홈은 노드 로컬 영속 볼륨으로 둔다

상태: 확정

## 맥락

세션의 홈 디렉터리(`/home/work`)를 어디에 둘 것인가. 처음에는 NFS 기반 RWX 볼륨에 두었다.
어느 노드에 뜨든 같은 홈을 보니 깔끔했다.

실제로 학습을 돌리자 문제가 드러났다. conda/pip 설치, 체크포인트 저장, 작은 파일 다수를
다루는 작업에서 NFS 지연이 그대로 체감됐다. 홈에 데이터를 두고 DataLoader를 돌리면
더 심했다.

## 결정

- `/home/work`는 **노드 로컬**에 둔다. 세션마다 별도 PVC(`local-path`)를 잡는다.
- 세션을 **중지해도 홈은 남고**, **삭제할 때만** 정리한다.
- 영속·공유가 필요한 데이터는 `~/nfs`(RWX NFS)에 둔다.
- 데이터셋은 `~/datasets`에 읽기 전용으로 마운트한다.
- `/dev/shm`은 메모리 기반으로 따로 마운트한다.

## 이유

- 홈은 "빠르게 읽고 쓰는 작업 공간", `~/nfs`는 "느려도 남는 공간"으로 역할을 갈랐다.
  하나로 둘 다 만족시킬 수 없다.
- 중지 후 재개는 흔한 사용 패턴이다. 중지할 때 홈이 날아가면 세션 중지 기능 자체가
  쓸모없어진다.
- `/dev/shm` 기본값 64MB로는 PyTorch DataLoader가 bus error로 죽는다. 홈과 별개로
  반드시 필요하다.

## 대안

- **NFS 홈 유지**: 노드에 묶이지 않는다. 성능이 받쳐주지 않았다.
- **emptyDir**: 가장 빠르지만 중지 시 소멸한다. 영속 홈이 필요 없는 배포에서는
  `sharedHome: false`로 이 모드를 쓸 수 있게 남겨 두었다.

## 결과

- 세션이 **노드에 묶인다.** 중지된 세션을 재개하거나 자원을 변경할 때 원래 노드로만 갈 수
  있다(`node_pinned`). 그 노드가 꽉 차면 사용자가 할 수 있는 일이 다르므로 오류 코드를
  따로 두었다.
- 중단 세션이 노드 디스크를 계속 점유한다. `quota.maxStoppedSessions`로 개수를 제한하고,
  `nodeCleaner`가 임계 초과 시 오래된 것부터 정리한다.
- 세션 홈은 백업 대상이 아니다. 사용자에게 산출물은 `~/nfs`나 볼륨에 두라고 안내한다.
