# ADR-0002. 도메인 상태는 MySQL에 둔다

상태: 확정

## 맥락

사용자, 조직, 팀, 지갑, 오퍼링, 감사 로그 같은 도메인 상태를 어디에 둘 것인가.
쿠버네티스에는 etcd가 있고 CR로 표현할 수도 있다.

## 결정

도메인 상태는 **MySQL**에 둔다. 클러스터는 실행 엔진으로만 쓴다.

## 이유

- 크레딧 차감, 계층 배분, 기간 집계는 트랜잭션과 조인이 필요하다. etcd/CR로는
  "이 팀의 이번 달 사용량을 사용자별로 묶어서" 같은 질의를 감당할 수 없다.
- 감사 로그와 과금 내역은 보존 기간이 길고 양이 많다. etcd에 넣을 성질이 아니다.
- 백업·복구가 명확하다. 덤프 하나로 끝난다.
- 승인 구간 직렬화에 `GET_LOCK`을 쓸 수 있다. 별도 분산 락 인프라가 필요 없다.

## 대안

- **etcd/CR에 전부 저장**: 컴포넌트가 하나 줄지만 질의·집계·보존에서 막힌다.
- **PostgreSQL**: 기능적으로 더 낫다. 다만 배포 대상 환경에서 MySQL 운영 경험이 더
  많았고, 차트 번들 기준으로 선택지를 하나로 좁히는 편이 낫다고 봤다.

## 결과

- MySQL이 단일 장애점이다. 복구 계획에서 최우선으로 다룬다([operations.md](../operations.md#백업)).
- 스키마 변경은 번호순 마이그레이션으로만 한다. 롤백 스크립트가 없으므로 파괴적 변경은
  두 릴리스에 나눠서 한다.
- 클러스터와 DB가 어긋날 수 있다. 리컨실러가 주기적으로 맞춘다.
