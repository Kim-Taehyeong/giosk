# ADR-0001. 세션을 네이티브 Pod로 실행한다

상태: 확정

## 맥락

사용자에게 GPU 작업 환경을 나눠 주는 방법은 여러 가지다. 우리가 실제로 놓인 조건은
"이미 쿠버네티스 클러스터가 있고, GPU 노드도 그 안에 있다"였다.

## 결정

세션을 **네이티브 쿠버네티스 Pod**로 띄운다. 커스텀 리소스(CRD)나 오퍼레이터를 만들지
않는다. Giosk는 kube-apiserver를 호출하는 평범한 웹 백엔드다.

## 이유

- 스케줄링, 자원 제한, RBAC, 스토리지, 노드 어피니티를 전부 쿠버네티스가 이미 한다.
  다시 구현할 이유가 없다.
- GPU 생태계(device-plugin, GFD, HAMi, DCGM)가 전부 쿠버네티스 위에 있다. Pod로 띄우면
  그대로 얹힌다.
- 문제가 생겼을 때 `kubectl describe pod`으로 바로 볼 수 있다. 자체 스케줄러를 만들면
  디버깅 창구도 직접 만들어야 한다.
- 운영자가 이미 아는 도구로 개입할 수 있다.

## 대안

- **CRD + 오퍼레이터**: 선언적이고 GitOps에 어울린다. 다만 사용자 대면 SaaS 형태의
  기능(크레딧, 승인 흐름, 조직 계층)은 결국 웹 백엔드가 필요하다. 컨트롤 플레인이 둘로
  갈라지고, 상태가 CR과 DB에 나뉘어 정합성 문제가 생긴다.
- **자체 스케줄러 / VM 기반**: 통제는 세지만 GPU 생태계와 노드 관리까지 전부 떠안는다.
  [ADR-0006](0006-vm-leasing-deferred.md) 참고.

## 결과

- 세션의 진실은 Pod 상태에 있고, DB는 그것을 반영한다. 둘이 어긋날 수 있어
  `RunPhaseReconciler`가 주기적으로 맞춘다.
- 세션 생성은 원자적이지 않다(검사한 뒤 예약하고 Pod를 만든다). 동시 요청 경합을 막기 위해
  승인 구간을 네임드 락으로 직렬화하고 예약을 먼저 기록한다.
- 쿠버네티스가 없는 환경은 지원하지 않는다.
