# ADR-0003. 전용 GPU와 공유(HAMi) GPU를 분리 집계한다

상태: 확정

## 맥락

GPU 한 장을 통째로 주는 경우와 HAMi로 쪼개 주는 경우가 한 클러스터에 섞여 있다.
"이 클러스터에 GPU가 몇 장 남았나"라는 질문의 답이 두 경우에 다르다.

HAMi는 자기가 관리하는 GPU의 capacity를 실제 물리 개수보다 크게 광고한다(분할 수만큼).
이걸 그대로 물리 개수로 쓰면 가용량이 부풀려진다.

## 결정

- 물리 GPU 개수는 **GPU Feature Discovery 라벨**(`nvidia.com/gpu.product`)에서 읽는다.
  HAMi가 광고하는 capacity는 쓰지 않는다.
- 전용 가용량은 **정수**, 공유 가용량은 **소수**로 따로 계산해 따로 보여준다.
- 전용 GPU 요청 상한은 클러스터 합계가 아니라 **단일 노드의 유휴 최대치**로 잡는다.
- 공유 세션은 `share_mode=hami`로 표시된 노드에만 배치한다.

## 이유

- 세션은 여러 노드에 걸쳐 뜰 수 없다. 합계로 상한을 잡으면 영원히 스케줄되지 않을 요청을
  승인하게 되고, 사용자는 Pending에 걸린 세션을 보며 이유를 알 수 없다.
- 두 자원을 한 숫자로 합치면 어느 쪽도 정확하지 않다. "3.5장 남음"은 전용 세션 사용자에게
  의미가 없고, "3장 남음"은 공유 사용자에게 부정확하다.

## 대안

- **HAMi로 전부 통일** — 모델이 단순해진다. 그러나 전용이 필요한 워크로드(대형 모델,
  분산 학습)가 실제로 있고, 분할 오버헤드도 있다.
- **전용만 지원** — GPU가 부족한 환경에서 활용률이 크게 떨어진다.

## 결과

- 오퍼링의 `gpu_type`은 노드 라벨 값과 **글자 단위로** 같아야 한다. 다르면 전용은
  잡히는데 공유만 "가용 없음"이 되고, 아무 로그도 남지 않는다. 이 함정은
  [troubleshooting.md](../troubleshooting.md)에 별도로 적어 두었다.
- 콘솔은 두 가용량을 구분해 표시한다.
- HAMi 없이도 전용 GPU만으로 운영 가능하다(`hami.install: false`).
